This story is a soundness-sensitive compiler change, so the implementation is stopped. No files were edited, and `./x test tidy` was not run.

The work is in the type checker and the MIR builder. `check_expr_array` and `check_expr_repeat` in `compiler/rustc_hir_typeck/src/expr.rs` decide whether a `[C; 0]` expression of type `!` makes the following code unreachable. That flag is then used when lowering HIR to MIR and when emitting later bounds checks. Code that computes types, MIR, or generated code is soundness-sensitive, including when the visible bug is an incorrect unreachable mark or an elided bounds check. Implementation of that behavior is banned.

The route for this kind of change is the [#llm-mentoring Zulip](https://rust-lang.zulipchat.com/#narrow/channel/606558-llm-mentoring/). A named reviewer, a regression test, or later editing does not permit the compiler change.

Two earlier gates also block any edit, including a regression test:

- No reviewer has been named in this conversation. Name someone who already agreed to review it before any repository change.
- The story also asks for new source comments in the compiler. Those comments have to be written by a person; they will not be generated here.

After a reviewer is named, the only permitted next step is a failing regression test, left in the tree, with its failure observed. The type-checker and MIR changes still stay stopped after that.

Text originally produced by an LLM, including tests, diagnostics, comments, and documentation, cannot be contributed upstream even if a person later edits it.
